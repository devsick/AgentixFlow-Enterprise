# Communication and Streaming Architecture: Analysis & Design

This documentation describes the current state and the planned communication model for streaming agent responses to the user. The goal is granular control over which information (text, status, tool calls) is sent to the user and when.

## 1. Core Concept: The `streaming_policy`

The system uses `StreamMode` logic to decide how a node (and thus the agent behind it) communicates. The policy is determined based on the node name or explicit metadata.

### Stream Modes (`src/shared/streaming_policy.py`)

| Mode | Behavior | Objective |
| :--- | :--- | :--- |
| `live` | Streams every LLM text chunk immediately (`on_chat_model_stream`). | Standard for chat agents. |
| `final_only` | Does not stream internal chunks. Only outputs the finished `AIMessage` at the end of the node. | For agents that should remain "silent" until the result is determined. |
| `status_only` | Does not stream text chunks. Only outputs status information (or the final message). | For function nodes/tool agents that should only tell the user what they are currently doing. |

---

## 2. Communication Graph & Event Flow

The data flow from the LLM response to user streaming follows this path:

### A. Agent Level (`src/graphs/pure_chat/agents/chat_agent.py`)
The agent performs the actual LLM call (via `self.llm.ainvoke`). 
- **Output:** An `AIMessage` (or an `AIMessageChunk` during streaming).
- **Important:** The agent itself is still "dumb" regarding the streaming policy; it simply provides the data generated by the LLM.

### B. Node Level (`src/graphs/pure_chat/nodes/chat_node.py`)
The node acts as a wrapper for the agent and prepares the data for the graph state.
- **Action:** Calls `agent.run(messages)`.
- **Output:** A dictionary containing the new `AIMessage` and `metadata` (tokens, reasoning, tool calls).
- **Integration:** The `@observe_node` decorator (`src/shared/node_wrapper.py`) is used here to track the lifecycle (`node_started`, `node_finished`).

### C. Streaming Translator (`src/api/streaming_translator.py`)
This is the central instance that monitors LangGraph events (`astream_events`) and converts them into the OpenAI-compliant SSE format.

**The current (faulty/incomplete) flow:**
The `stream_translator` iterates over `graph.astream_events`. Currently, it primarily reacts to:
- `on_chat_model_stream`: Here, chunks are sent directly to the user.

**The Problem:** The translator does not yet know sufficiently which `streaming_policy` applies to the currently running node. It blindly streams `on_chat_model_stream` events, which contradicts the goal that a `status_only` node should not send text chunks.

### D. API Endpoint (`src/api/chat_completions.py`)
The endpoint starts the process and establishes the connection to the client. It uses the `get_stream_mode(event)` function to extract the policy from the event metadata.

## 3. Detailed Communication Workflow (Target State)

To achieve the goal, the `stream_translator` must consider the `streaming_policy` at the event level.

### Event Matrix for the `stream_translator`

| Event Type | Context / Policy | Translator Action | Target Output |
| :--- | :--- | :--- | :--- |
| `on_chat_model_stream` | `live` | Extract & send chunk. | `delta: {content: "..."}` |
| `on_chat_model_stream` | `final_only` | **Ignore.** | (No output) |
| `on_chat_model_stream` | `status_only` | **Ignore.** | (No output) |
| `on_chain_end` (Node) | `status_only` | If the node has a status message, send it. | `delta: {content: "Searching..."}` |
| `on_chain_end` (Node) | `any` | Send the node's final `AIMessage`. | `content: "Done!"` |

### Example: A "Function Agent" (Status-only)

1. **Node starts:** `chat_node` is called.
2. **Agent works:** `chat_agent` calls the LLM. The LLM generates text chunks.
3. **Streaming event:** `on_chat_model_stream` fires.
4. **Translator logic:**
   - The translator checks `event["metadata"]["langgraph_node"]`.
   - It sees: Mode is `status_only`.
   - **Result:** It discards the `on_chat_model_stream` events. The user sees nothing.
5. **Node ends:** `on_chain_end` fires.
6. **Translator logic:**
   - It sees the final `AIMessage` in the state (e.g., "I found the file").
   - It sends this as a single, final chunk.
   - **Result:** The user only sees: "I found the file." (No typed text streaming).

---

## 4. Summary of Responsibilities

- **`streaming_policy.py`**: Defines the allowed modes.
- **`node_wrapper.py`**: Ensures that metadata (node name) ends up in the state so it can be used in streaming.
- **`chat_agent.py`**: Provides the raw data (Messages).
- **`streaming_translator.py` (Critical!)**: Must implement the logic that filters `on_chat_model_stream` events based on the `streaming_policy`.
- **`chat_completions.py`**: Orchestrates the start.

**Important for implementation:** 
`thinking` (Reasoning) and `tool_calls` remain untouched. This means that even in `status_only` mode, reasoning chunks or tool call information could be passed through (if technically implemented that way) if desired. The policy primarily refers to the `content` property of the `AIMessage`.
